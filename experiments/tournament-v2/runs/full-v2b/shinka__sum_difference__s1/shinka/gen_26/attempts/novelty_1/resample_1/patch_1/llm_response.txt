<DESCRIPTION>
The current program spends its entire Phase 1 budget (~25s) enumerating structured seeds and only tracks a single `best` seed by the full score (which includes the small size bonus). This means it often starts refinement from the first seed that happens to beat the incumbent, rather than from the seed with the highest *pure* log-ratio (which is what actually drives the objective). 

Idea: instead of greedily keeping only one seed, collect the top-K (K=8) seeds ranked by their pure `log|A-A|/log|A+A|` (excluding the size bonus), then run the local-search refinement from each of these K seeds in order within the remaining budget. This is the recommendation from the feedback: rank by the pure log-ratio, and use the size bonus only as a tiebreaker.

Implementation:
1. Add a `_score_pure(a)` helper that returns `log|A-A|/log|A+A|` without the size bonus.
2. In Phase 1, maintain a small priority list `top_seeds` of (pure_score, cand) keeping the top K=8 unique candidates.
3. In Phase 2/3, iterate over `top_seeds` (sorted descending by pure score) and run `_local_search` from each, within the remaining budget, keeping the overall best by full score.
4. Keep the existing random-restart loop for the leftover budget after refining all top-K seeds.

This preserves the existing structure and only changes the seed selection strategy to be ratio-aware and diverse.

        return 0, 0

            diffs.add(ai - aj)
            diffs.add(aj - ai)
            sums.add(ai + aj)
    return len(diffs), len(sums)


def _score(a):
    a = list(set(a))
    n = len(a)
    if n < 2:
        return 0.0
    nd, ns = _stats(a)
    if ns <= 1:
        return 0.0
    return math.log(nd) / math.log(ns) + (1 - 1 / n) / 100
