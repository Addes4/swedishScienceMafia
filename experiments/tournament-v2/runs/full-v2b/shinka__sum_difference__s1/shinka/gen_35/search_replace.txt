unified_deadline_budget</NAME>

<DESCRIPTION>
The current program has a single 90-second local-search deadline plus an unbounded structured-construction phase (the prime loop up to p=200 with `_multi_reflect`, the bounded Sidon loop up to n=200 with span up to 1e6, and the greedy Sidon loop). The `_multi_reflect` calls in particular can be very expensive (up to 3 rounds × 20 candidates × `_score` over O(n^2) elements). Combined with the 90s local search, this risks exceeding the 120s harness budget. To fix this and to make sure the local search actually gets its full share of time, I introduce a single shared wall-clock budget `DEADLINE = t0 + 105` at the top of `solve()`, and add hard `time.time() < DEADLINE` guards inside the structured-construction loops (primes, bounded Sidon, greedy Sidon) and inside the local-search inner loop. This leaves a ~15s margin for the harness and prevents the timeout failure mode observed in prior generations (Gen 23).

nested_interval_seed_pool</NAME>
<DESCRIPTION>
The prior nested-interval construction (union of `base + off` for tightly packed offsets) is a strong structural seed that the current crossover program does not exploit at all. Because the base is a Sidon-like set with all internal differences distinct, the difference set of the union is essentially the union of block-internal differences plus cross-block differences; tightly packed offsets make many sums collide, which shrinks |A+A|. I add a seed-pool generator that builds such nested-interval sets over a grid of (base size, block count) and injects the best candidates into `best`. This gives the local search a much better starting point, which is the key lever for improving the ratio given the ~100s local-search budget. The generator respects `DEADLINE` so it cannot blow the budget.

def _nested_seed_pool(deadline, rng):
    """Return (best_set, best_score) from nested-interval Sidon-like constructions.

    Build a small Sidon-like base B (all internal differences distinct) and
    replicate it at tightly packed offsets off = k*M. The union A = B + {off}
    has a large difference set (all base differences plus cross-block
    differences) while the sum set collapses because the offsets are close.
    """
    best = None
    best_score = -1.0
    base_sizes = [6, 8, 10, 12, 16, 20, 24, 28, 32]
    block_counts = [4, 6, 8, 12, 16, 24, 32, 48, 64]
    for bn in base_sizes:
        if time.time() > deadline:
            break
        for seed in range(2):
            base = _greedy_sidon(bn, seed=seed * 997 + bn)
            if len(base) < 3:
                continue
            base = sorted(base)
            base_span = base[-1] - base[0]
            M = base_span + 1
            for K in block_counts:
                if time.time() > deadline:
                    break
                if bn * K > 3800:
                    continue
                offsets = [k * M for k in range(K)]
                A = []
                for off in offsets:
                    for b in base:
                        A.append(b + off)
                if len(set(A)) < 2:
                    continue
                s = _score(A)
                if s > best_score:
                    best_score = s
                    best = sorted(set(A))
                # A few random perturbations of a single offset to encourage
                # extra sum collisions without breaking the structure.
                for _ in range(2):
                    if time.time() > deadline:
                        break
                    off2 = offsets[:]
                    j = rng.randrange(len(off2))
                    off2[j] += rng.randint(-M // 2, M // 2)
                    if len(set(off2)) < len(off2):
                        continue
                    A2 = []
                    for off in sorted(off2):
                        for b in base:
                            A2.append(b + off)
                    if len(set(A2)) < 2:
                        continue
                    s2 = _score(A2)
                    if s2 > best_score:
                        best_score = s2
                        best = sorted(set(A2))
    return best, best_score

final_polish_deadline_guard</NAME>
<DESCRIPTION>
The final polishing block (shifts and `_multi_reflect`) runs after the local search without any time guard. `_multi_reflect(best, max_rounds=6)` can be expensive on a large best set and, combined with the earlier phases, risks exceeding the budget. I wrap the final polish in a `time.time() < DEADLINE - 1` guard and reduce `max_rounds` to 4 so the polish step is bounded and cannot push the total runtime past the 105s budget. This preserves the improvement from reflection while guaranteeing the program returns in time.
